# Modern UI Redesign Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking. Before writing any code, view `/mnt/skills/public/frontend-design/SKILL.md` if available in your environment — this plan follows its token-first process.

**Goal:** Replace the widget's bare shadcn defaults with an intentional design system — a defined color/type/spacing scale, a distinctive pulsing waveform as the one signature visual element, and consistent polish across all four widget states plus the config dialog.

**Design tokens (see conversation for full rationale):**
- Color: surface `#F7F8FA`, ink-indigo `#3730A3` (primary actions), signal red `#E5484D` (recording only), sage `#2F9E68` (done/success), graphite `#1F2430` (headings), slate `#6B7280` (secondary text)
- Type: Inter (bold/tight tracking) for headings, Inter regular for body, `ui-monospace` for the elapsed timer
- Signature element: the waveform — calm muted dots when idle, amber→red volume-reactive pulse when recording

**Architecture:** shadcn/ui components (`Button`, `Input`, `Dialog`, etc.) are already wired to a set of CSS custom properties — `--primary`, `--primary-foreground`, `--destructive`, `--radius`, and so on — defined in `:root` by the `shadcn init` step in plan 01. **This plan updates those existing variables to the new palette rather than introducing separate hardcoded color names**, which is what makes `<Button>` (and every other shadcn component) pick up the new look automatically, with correct padding/focus-ring/hover states intact, and zero per-instance className color overrides. Only genuinely new tokens (the `recording`/`done` accent colors that don't map to an existing shadcn slot, the waveform's own inline colors, and the monospace font) are added as new Tailwind extensions; everything else reuses shadcn's own variable names.

Additionally, the Recording state drops the window's chrome (title bar, card border) entirely and shrinks the Tauri window itself down to a small pill, relying on `transparent: true` (set in plan 01) so only the pill's own rounded background is visible against otherwise-transparent space — matching Notion's floating recording indicator rather than a shrunken dialog. This requires lifting widget state up to `App.tsx` so window-level decisions (size, whether to render the title bar) can react to it.

**Tech Stack:** Tailwind CSS, shadcn/ui (restyled via its own CSS variables, not replaced or overridden with parallel color names)

```tsx
// src/App.tsx (replace the root component)
import { useEffect, useRef, useState } from "react";
import { getCurrentWindow, LogicalSize } from "@tauri-apps/api/window";
import { TitleBar } from "@/components/TitleBar";
import { RecorderWidget } from "@/components/RecorderWidget";
import { ConfigDialog } from "@/components/ConfigDialog";
import { configNeedsSetup, saveConfig, type AppConfig } from "@/lib/config";

type WidgetState = "idle" | "recording" | "processing" | "done";

// Tauri's setSize() has no built-in transition — it snaps instantly. To make
// the shrink/grow feel intentional rather than jarring, step through
// intermediate sizes over a short duration with an ease-out curve. This is a
// manual animation of the actual OS window frame, not a CSS transition (CSS
// can't touch native window dimensions, only content drawn inside them).
function easeOutCubic(t: number): number {
  return 1 - Math.pow(1 - t, 3);
}

async function animateResize(
  from: { width: number; height: number },
  to: { width: number; height: number },
  durationMs = 180
) {
  const win = getCurrentWindow();
  const start = performance.now();

  return new Promise<void>((resolve) => {
    function step(now: number) {
      const elapsed = now - start;
      const t = Math.min(elapsed / durationMs, 1);
      const eased = easeOutCubic(t);
      const width = from.width + (to.width - from.width) * eased;
      const height = from.height + (to.height - from.height) * eased;
      win.setSize(new LogicalSize(width, height));
      if (t < 1) {
        requestAnimationFrame(step);
      } else {
        resolve();
      }
    }
    requestAnimationFrame(step);
  });
}

const WINDOW_SIZES: Record<WidgetState, { width: number; height: number }> = {
  idle: { width: 400, height: 300 },
  recording: { width: 224, height: 56 },
  processing: { width: 260, height: 56 },
  done: { width: 400, height: 300 },
};

function App() {
  const [showConfigDialog, setShowConfigDialog] = useState(false);
  const [widgetState, setWidgetState] = useState<WidgetState>("idle");
  const previousSizeRef = useRef(WINDOW_SIZES.idle);

  useEffect(() => {
    configNeedsSetup().then(setShowConfigDialog);
  }, []);

  useEffect(() => {
    const targetSize = WINDOW_SIZES[widgetState];
    animateResize(previousSizeRef.current, targetSize).then(() => {
      previousSizeRef.current = targetSize;
    });
  }, [widgetState]);

  const handleSave = async (config: AppConfig) => {
    await saveConfig(config);
    setShowConfigDialog(false);
  };
  const handleSkip = () => setShowConfigDialog(false);

  // Recording and Processing: no card, no title bar — the pill itself
  // (rendered inside RecorderWidget) is the entire visible window, floating
  // on transparent space, matching Notion's own recording/processing
  // indicator rather than looking like a shrunken dialog.
  if (widgetState === "recording" || widgetState === "processing") {
    return (
      <div className="h-screen w-screen flex items-center justify-center bg-transparent">
        <RecorderWidget onStateChange={setWidgetState} />
      </div>
    );
  }

  return (
    <div className="h-screen flex flex-col rounded-lg overflow-hidden border shadow-widget bg-background text-foreground">
      <TitleBar />
      <div className="flex-1 p-5">
        <RecorderWidget onStateChange={setWidgetState} />
      </div>
      <ConfigDialog open={showConfigDialog} onSave={handleSave} onSkip={handleSkip} />
    </div>
  );
}

export default App;
```

**Caveat worth testing on real hardware, not just assuming it works:** stepping `setSize()` at animation-frame rate is a manual re-implementation of something the OS doesn't natively support animating, so smoothness can vary by platform/compositor — generally fine on macOS, but some Linux window managers (particularly under X11, less so Wayland/PipeWire-adjacent compositors) can look stepped rather than fluid, and rapid resize calls have a small chance of visual tearing depending on the WM. If it looks janky in practice rather than smooth, the fallback is simply calling `win.setSize()` once with the final target size (no animation) — worse-looking but bulletproof. Treat the animated version as a nice-to-have, not something to fight hard for if a given Linux setup renders it poorly.

Note: `ConfigDialog` is intentionally omitted from the chrome-less recording branch — it's only ever shown at first launch, well before a recording could be in progress, so this isn't a regression in practice, but worth knowing if that assumption ever changes.

```tsx
// src/components/Waveform.tsx (add a compact prop, shrink canvas + bar count when set)
interface WaveformProps {
  active: boolean;
  compact?: boolean;
}

export function Waveform({ active, compact = false }: WaveformProps) {
  // ... existing setup unchanged ...
  const canvasWidth = compact ? 90 : 320;
  const canvasHeight = compact ? 20 : 60;
  // pass a smaller fftSize when compact so there are fewer, chunkier bars
  // appropriate to the docket's scale:
  analyser.fftSize = compact ? 32 : 64;

  // in the draw() loop's fillStyle logic:
  const rootStyles = getComputedStyle(document.documentElement);
  const destructiveHsl = rootStyles.getPropertyValue('--destructive').trim();

  dataArray.forEach((value, i) => {
    const intensity = value / 255;
    const height = Math.max(compact ? 1.5 : 2, intensity * canvas.height);
    const color = intensity < 0.15
      ? "hsl(220 9% 80%)"
      : intensity < 0.5
        ? "#F59E0B"
        : `hsl(${destructiveHsl})`;
    ctx.fillStyle = color;
    ctx.beginPath();
    const x = i * barWidth + barWidth / 2;
    const y = canvas.height / 2;
    ctx.arc(x, y, height / 2, 0, Math.PI * 2);
    ctx.fill();
  });

  return <canvas ref={canvasRef} width={canvasWidth} height={canvasHeight} />;
}
```
